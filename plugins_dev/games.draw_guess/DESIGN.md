# 你画我猜插件设计

状态：本轮功能已完成，正式版本 0.1.2，当前范围见第 13 节。更新日期：2026-11-02。

本文第 1～12 节保留产品方向与设计讨论。已实现能力以第 13 节和使用说明为准，其余属于后续事项。

## 1. 已确定的方向

- 通用绘画与图片标注能力内置于 LimeA，小游戏以可选插件提供。
- 用户和当前聊天角色都可以画、也可以猜，轮流进行。
- 用户画画时，模型根据不断更新的画面猜测，不必等用户画完。
- 模型画画时，可以看到自己实际画出的画面，再补画、修改或等待猜测。
- 不要求模型画得漂亮；抽象的画法也是乐趣，不以画功作为上线门槛。
- 使用较长的猜测总时长，避免过短倒计时打断创作。
- 开始前单独调用一次模型生成一批词，后台保存；每轮由画画的一方三选一。
- 不提供自命题，避免过长、过难或无法表达的题目。
- 不设积分、比分、速度奖励或输赢排行榜。结束只说明是否猜中、答案和画作。

## 2. 通用能力与插件分工

| 所属                            | 职责                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| LimeA 通用画板                  | 笔画、基础图形、颜色与粗细、擦除、撤销与重做、可编辑保存、画面快照；后续复用到图片标注 |
| LimeA 模型适配层                | 沿用已配置的模型与角色，检查图片输入能力，发送画面和接收绘画操作，不绑定单一供应商     |
| Harness（智能体运行与编排内核） | 模型请求、工具执行、取消、等待、错误反馈和恢复；承载隔离上下文及请求生命周期           |
| 插件后台                        | 词库、候选分配、选词、双方角色、计时、猜测判定、揭晓、轮次记录                         |
| 插件界面                        | 三选一、画板入口、猜测输入与气泡、剩余时间、结果和续局选项                             |

通用画板不认识答案、题库或游戏轮次；插件通过宿主公开接口使用画板。模式配置决定能力是否开放，安装游戏不能自动让其他模式获得游戏工具。

通用画板可以提供文字、图片背景、箭头和框选，游戏采用受限工具集合：首版允许笔画和基础图形，关闭文字工具、图片导入与粘贴，避免直接贴答案或成品。手写文字无法完全靠工具限制，按休闲游戏规则提示不写答案，不承诺自动防作弊。

## 3. 复用方案与当前缺口

优先验证 Excalidraw（开源白板编辑器）。它提供自由绘画、基础图形、擦除、撤销重做和图片导出，可替代通用编辑器的主要基础功能，采用 MIT（宽松开源许可证）。接入成本主要在主题、工具裁剪、资源打包和宿主适配；实际体积、交互与兼容性需要本地验证。[官方项目](https://github.com/excalidraw/excalidraw)

模型的结构化图形可通过其程序化元素接口接入；该接口仍标为测试阶段，存在变更风险，应锁定验证过的版本，并由宿主封装，避免插件直接依赖库内部数据结构。自由笔画的接入另行验证，不假设简化元素转换接口支持全部笔画类型。[程序化创建元素](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/excalidraw-element-skeleton)

模型观察复用现有画面导出功能，生成尺寸受控的快照，包含实际绘制结果。[官方导出接口](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/utils/export)

备选为 Konva（二维绘图库）及其 React（界面开发库）绑定，可复用图形、事件和画布渲染，但需要更多编辑器交互与状态适配。仅在完整编辑器的定制成本过高时重新评估，不同时引入两套。[官方接入文档](https://konvajs.org/docs/react/index.html)

以上项目都有可查的官方源码或文档；正式引入时仍须核对发布、维护和兼容状态。当前不安装依赖、不固定版本，也不从零编写通用画布引擎。

可参考现有[五子棋](../games.gomoku/README.md)的会话绑定、后台命令、托管数据库、设置窗口与恢复流程，但不复制整套游戏实现，也不要求用户安装其他游戏。

当前宿主已经有画布面板占位、小游戏面板、插件工具及独立设置接口。插件画板快照进入模型、私有选词上下文、持续观察调度等仍需宿主实现，不能只在插件里增加一个页面便视为完成。正式接口版本在实现时确定。

## 4. 词库生成与三选一

开始游戏时发起独立出题请求，只传生成规则和必要的去重信息，不带当前聊天历史。可使用当前配置的模型，但与陪玩请求采用不同上下文；插件不读取模型密钥、不自行调用供应商。

出题规则：短、具体、常见、适合简笔画表达，避免长句、生僻专名、复杂抽象概念和必须依靠文字才能表达的题目。后台校验长度、结构、重复项与候选数量；无效批次不能直接开始游戏。生成失败可重试或退出，不退回自命题。

首次生成一批词，后台随机取三个交给本轮画画的一方。词库不足时，在轮间补充，不干扰正在进行的回合。批量大小、字数范围和类别分布是待验证参数。

| 阶段           | 用户可见                           | 陪玩模型可见                       |
| -------------- | ---------------------------------- | ---------------------------------- |
| 词库准备       | 准备状态，不含词库                 | 不含词库                           |
| 用户选词、作画 | 本轮三个候选、选中词、画面         | 公开游戏状态与画面，不含候选或答案 |
| 角色选词、作画 | 公开游戏状态与画面，不含候选或答案 | 本轮三个候选、选中词、画面         |
| 本轮揭晓       | 选中词、结果、画作                 | 选中词、结果、画作                 |

“双方看不到”指完整后台词库及对方尚未揭晓的题目；画画的一方必须知道本轮候选和选中词。出题请求必然接触它生成的词，但这些内容不进入陪玩模型的上下文。

三个候选一经展示，整组都从本场后续候选中移除，包括未选中的两个，防止交换角色后出现已知题目。候选曝光和消耗状态先持久保存，重启不能重新分配已展示候选。

## 5. 私有上下文与公开记录

宿主根据“本轮画家／猜测者”构造明确的数据视图，后台校验调用身份；不能把词库发到界面后仅靠隐藏控件保密，也不能靠一句“不要偷看”隔离模型上下文。

- 出题上下文、角色作画上下文和猜测上下文分开。
- 每轮创建新的游戏私有上下文，可继承角色设定和公开聊天，不继承旧轮的候选、私有选词或绘画推理。
- 模型猜画时只获得画面、公开状态及先前公开猜测，不获得绘画操作中的语义名称、答案或同义词。
- 模型画画时的选词、私有推理和含答案的工具参数不进入普通聊天、可展开工具详情、会话压缩摘要或公开导出。
- 快照不包含选词栏；文件名、元素标签、图片元数据和替代文本也不能带出答案。
- 公开展示的内容由允许字段构造，不能将整段私有响应流先显示再做字符串替换。作画中的自由文本暂不直接公开，避免顺口说出答案。
- 揭晓后，选中词、画作引用、猜测和结果可进入公开历史；未选候选与剩余词库仍不公开。

后台私有数据是游戏公平性边界，不是对本机管理员或已获信任插件的加密保险箱。正式实现需同时验证实时展示、持久历史、上下文压缩和重启恢复，避免其中一条路径泄露。

## 6. 时长与生命周期

已确定使用更长的总时长。建议先提供 3／5／10 分钟，默认 5 分钟；不限时是否开放待确认。这些数值尚未锁定。

选词、画板初始化不计时。用户确认开始画画时计时；角色作画则在首批可展示的绘画准备好并开始呈现时计时，避免准备期占用猜测时间。准备请求仍遵守宿主的请求超时与取消机制。

开始后按真实经过时间倒计时，包含思考与等待；模型不会因为一次请求慢而自动续时。总时长与观察频率分开设置。正常请求可在剩余时间内继续，不再额外设置固定猜测次数上限；技术错误仍按宿主错误策略处理。

后台拥有截止时间和终态，界面只负责显示。到时立即锁定本轮结果，不依赖模型回复来宣布结束。后台接纳猜测和到时事件的先后顺序决定是否有效，不采信客户端自报时间。

建议将“暂停”和“结束”作为明确操作；切换面板不自动开新局。隐藏面板是否暂停计时待实测确定。程序退出、异常或系统休眠后的恢复先进入暂停状态，显示最后保存画面，用户确认后继续；不自动恢复请求或补画。

基本流程：

```text
准备词库 → 确定本轮画家 → 三选一 → 准备画板
                                      ↓
                               绘画与猜测同时进行
                                      ↓
                          猜中／到时／主动揭晓
                                      ↓
                         保存结果、展示答案和画作
                                      ↓
                      再来一轮（默认交换）／下次再玩
```

暂停保留本轮，不揭晓；主动结束整场则停止请求、保存状态并显示已结束。是否主动揭晓与暂停必须是不同动作，避免误点泄题。

游戏轮次状态由插件管理，模型运行状态仍由 Harness 管理。等待用户选择或继续时不轮询模型；没有工具调用也不能被简单等同于整场结束，猜测、暂不猜和等待都是合法业务结果。

## 7. 用户画、角色猜

1. 用户从三个候选中选一个，开始作画。
2. 画板持续响应笔输入；模型请求进行中也能画、擦除和撤销。
3. 有明显画面变化时准备快照。可先验证约 2～3 秒的最短观察间隔，并结合停笔触发；无变化不重复请求，具体节奏按延迟和用量调整。
4. 每场最多一个游戏模型请求在途，只保留最新待观察画面，不积压每一笔对应的请求。
5. 模型看图后返回一个猜测，或表示暂时没有新猜测；界面简短展示，后台避免连续重复播报相同答案。
6. 请求完成后，若画面已更新且本轮仍有效，再观察最新画面。

新增笔画不取消正在进行的请求，否则持续绘画可能使模型永远答不出来。同一轮、同一画面世代的旧快照回答仍可接纳；清空重画、换轮、暂停或结束会使旧请求失效。请求绑定快照版本，不能把旧观察冒充最新画面。

用户猜词输入、控制事件和模型结果都经后台串行裁决。猜中或揭晓后立即停止后续调度；即使供应商未及时取消，迟到结果也不能影响下一轮。

## 8. 角色画、用户猜

角色通过私有上下文完成三选一，然后使用通用画板操作分批绘制：

```text
选词 → 提交一批绘画操作 → 宿主校验并绘制
                              ↓
                    返回实际画面快照及操作结果
                              ↓
                   模型观察 → 补画／修改／等待
                              ↑
                    用户猜测作为下一步反馈
```

首版操作以笔画、线段、椭圆、矩形、颜色、粗细，以及已有元素的修改和删除为主。一次可以提交多笔，不为动画的每一帧调用模型。宿主按批次顺序呈现过程，模型自行决定画什么、放哪里。

模型必须接收真实渲染出的快照，不能仅凭自己的操作列表假定效果。通用工具返回稳定元素标识和明确坐标范围，供后续修改；会话、本轮归属和状态版本由宿主绑定，避免要求模型猜测内部编号。

后台校验操作数量、坐标、样式和目标元素归属；错误反馈可纠正，重复提交不能重复绘制。原始脚本和任意页面代码不作为绘画输入。

用户在角色绘画期间可以随时输入猜测，不能修改角色画布。猜测在后台立即判定，不必等绘画请求结束。未猜中的公开猜测可随下一步请求送给角色帮助补画；同一场不并发启动第二个绘画请求。

模型画完后可以等待用户猜，不在没有变化或新输入时空转。猜中、到时或揭晓后取消未执行的绘画批次并拒绝迟到操作；不等待模型说一句话才显示结果。

## 9. 猜测判定与结果

建议首版使用词条的标准答案和经过校验的常见同义词，后台对完整猜测做规范化匹配，忽略必要的空白和标点差异；不做任意子串命中。角色返回结构化猜测，用户在独立猜测框输入。

宽泛近义、错别字和近似表达如何接受仍待确定。可评估独立的语义判定请求，但不能把答案注入正在猜画的模型；判定也必须遵守本轮有效性和截止时间。首版不为此复制另一套模型调用框架。

结果固定为“猜中了”“时间到了，答案是……”或“本轮已揭晓”，同时保留画作，展示“再来一轮 / 下次再玩”。没有得分、排名或谁更快的比较。角色可以在揭晓后自然回应一次，但回应失败不阻塞结果按钮。

再来一轮默认交换画家与猜测者，重新三选一；用户选择下次再玩后结束游戏运行。轮次历史属于原聊天，后续普通聊天可读取公开摘要，避免角色完全忘记刚才的游戏。

## 10. 持久化与中断

复用宿主托管的 SQLite（嵌入式关系数据库），不新建迁移框架。正式注册后按插件标识隔离数据库，迁移从 `1000` 起追加；此阶段不创建迁移或占用编号。

需要持久保存：词库与候选消耗、本轮选择、双方身份、时长和暂停信息、画板引用与版本、已接纳操作、猜测、结果、公开历史摘要，以及待执行请求的归属和状态。

画板可编辑内容由宿主统一保存，插件保存引用。大图片和素材通过宿主资源服务管理，不把每次观察快照全部塞进聊天正文；保留范围和清理策略在实现时确定。私有词库与公开历史分别投影，不能依靠前端删字段。

绘画操作先记录意图，再执行并保存结果；操作标识保证重复事件不会重复画。画布状态已保存、插件确认尚未完成时，通过操作记录核对，不盲目重放。重启从已保存画布恢复，未确认操作标为待核对。

## 11. 实施顺序与验收

按最小可用路径推进，不一次搭完空框架：

1. 宿主验证现成画板接入、保存、导出及模型读图；接受抽象画风，重点验证交互与实际图像反馈。
2. 建立最小插件流程：独立出题、候选隔离、用户三选一作画、角色持续猜测、揭晓和续局。
3. 接入角色私有选词、分批绘画、看图修改、用户随时猜测与双方轮换。
4. 完成独立设置、持久历史、恢复和真实桌面验证，再制作安装包并上架。

验收必须覆盖：

- 双方都能作画，模型思考不锁住用户画笔，角色能看到实际画面继续修改。
- 未曝光词库始终不进入陪玩请求；轮换、工具详情、压缩摘要、重启和公开导出不泄题。
- 已展示的三个候选全部退出本场后续分配，不因重启再次出现。
- 最多一个请求在途，长时间持续绘画仍能得到猜测，无变化时不空转。
- 猜中、到时、清空、暂停和换轮后的迟到响应不会污染当前状态。
- 绘画失败可纠正，重复操作不重复绘制，崩溃后保留可核对记录。
- 结果和两个选项立即可用，不依赖模型补充回应；结束后普通聊天仍有公开回顾。
- 角色和用户均无积分；模型不支持图片输入时在开始前说明，不能伪装成已经看见画面。
- 窄面板、键盘输入、输入法、主题切换和暂停恢复可用；不以调用真实付费模型作为自动化测试前提。

## 12. 后续需要确认的参数

- 时长档位、默认值以及是否提供不限时。
- 首轮谁画、是否允许手动切换顺序。
- 词库批量大小、词长和类别限制、同义词及近似答案处理。
- 模型观察间隔、快照尺寸、绘画批次大小和逐笔呈现速度。
- 隐藏面板是否暂停，以及草稿和历史画作的保留范围。
- 默认沿用会话模型与思考强度；是否提供独立的低延迟游戏配置，须明确告知用户，不能静默降档或切换模型。
- 画板依赖版本、宿主新增接口版本和正式插件标识。

开发阶段不登记市场条目；0.1.2 正式发布时已生成市场条目、图标和安装包。

## 13. 当前正式版本（0.1.2）

已实现双方轮流、后台生成词库、三选一、私有上下文、边画边猜、模型观察实际画面继续绘制、揭晓与续局、不计分、持久化和暂停恢复。

本次采用备选 Konva 10.9.1，原因是首版仅需基础图形与受限绘画工具，不需要完整白板编辑器的菜单、协作或字体资源。依赖和通用画板组件放在宿主，插件通过接口版本 8 使用，不重复携带绘图库。宿主提供画板文档格式与校验，插件将文档与轮次一起存入托管数据库；独立共享画作库留待通用画板页面落地。

首版参数：默认用户先画，可改为角色先画；3／5／10 分钟，默认 5 分钟；有新画面时至少间隔 2.5 秒观察，一场只允许一个私有模型请求在途；隐藏面板即暂停。角色分批显示图形，首批呈现时启动计时，尚未实现逐笔动画。

0.1.1 调整：用户选词即开始绘画和计时，取消二次开始按钮；旧版等待开始的存档继续后也直接进入画板。双方获得标准题目的字数提示，猜测模型只获得字数而非题目；图标工具栏复用宿主图标与滑动条组件，粗细可在 1～24 px 间调整，画板内支持 Ctrl+Z、Ctrl+Y 和 Ctrl+Shift+Z。出题时用深色遮罩和状态文案阻止误操作，暂停和结束仍可使用。

0.1.2 收尾：宿主颜料桶复用 q-floodfill（扫描线连通区域填充库）1.3.1，按 800×600 实际画面计算，不自行重写填充算法。该依赖使用 MIT、无运行时依赖，但发布较早，因此锁定版本并用真实桌面测试覆盖边界。填色存为有界、排序的行区段，不在恢复或删除轮廓后重新计算；同色点击不产生历史。插件只接收画板交互事件，用 Web Audio（浏览器音频接口）播放 CC0 本地素材；画笔声单循环、停笔停止，短音限制叠加，静音、隐藏和卸载取消迟到播放。面板提供音效、画笔声和音量设置，保存于本机界面偏好，不改变游戏数据库迁移。

持续落笔时约每 750 毫秒保存一次阶段画面，松手时保存完整笔画。画面与版本成对提交，避免把尚未保存的新画面归到旧版本；正在请求时只保留最新待观察画面。面板关闭通知失效时，后台在超过 5 秒未收到面板读取后暂停；睡眠唤醒和重启也需要用户主动继续。非法绘画先反馈一次让模型纠正，再次失败则暂停并保留画作。

模型私有请求由 Harness 提供工具执行范围内的能力，复用模型适配器和取消信号；词库及私有响应不进入公开聊天和普通模型正文诊断。插件记录每次请求的意图、结果和用量，当前私有调用用量尚未并入主聊天用量统计。

尚未实施：模糊语义判题、不限时、独立插件设置窗口、历史画作浏览与导出、图片背景标注、Work 画板入口。当前设置放在游戏开始区域；下一轮默认交换双方。它们不影响首版完整游玩，使用与验证见 [README](README.md)。
